# AI-VTUBER-Twitch-Companion — repository research

**Repository:** [gaetan-warin/AI-VTUBER-Twitch-Companion](https://github.com/gaetan-warin/AI-VTUBER-Twitch-Companion)  
**Commit inspected:** `23c18d639ffd975efa1a49aa2f4d3378b36108b6` (2025-11-08; shallow clone HEAD at inspection) [1]  
**Purpose:** A locally run AI VTuber/streaming companion: a browser-rendered Live2D avatar accepts typed, microphone, or Twitch chat prompts, asks an Ollama or Gemini model for responses, and speaks/animates those responses. It also includes document retrieval, streamer-oriented Twitch events, configuration, and optional computer actions. This purpose is corroborated by the actual Flask app, browser modules, listener, and utilities rather than README claims alone. [2] [3] [4] [5]

## Stack and architecture

- **Backend:** Python 3 application centered on `app.py`, with Flask routes, Flask-SocketIO and Eventlet for real-time events. The app imports Ollama and Google Generative AI directly and selects a provider in its request-processing code. A separate `listener/twitch_listener.py` process uses TwitchIO and a Socket.IO client to receive channel chat and relay relevant messages into the application. [2] [3] [6]
- **Frontend:** HTML template in `templates/avatar.html`, CSS, and modular browser JavaScript under `static/js/modules/`. Rendering uses PixiJS and the Pixi Live2D display integration with bundled Live2D/Cubism runtime files; the UI also uses jQuery, GSAP and Socket.IO client. Browser SpeechSynthesis provides spoken output, while microphone input uses `webkitSpeechRecognition`; `MediaRecorder` handles screen capture. [4] [7] [8]
- **Retrieval and files:** `utils/rag_handler.py` loads PDF/TXT content, embeds text with SentenceTransformers (`all-MiniLM-L6-v2` by default), indexes embeddings in FAISS and uses BM25; it fuses ranked results using reciprocal-rank-style scores. `utils/file_manager.py` manages uploaded RAG documents under `static/doc` and generated files under `output`, with Socket.IO list/upload/delete events. [9] [10]
- **Configuration and startup:** `.env.example` supplies persona, model, server/socket, Twitch, language, wake-word, celebration and feature settings. `app.py` loads `.env` (or falls back to `.env.example`), initializes Flask, Socket.IO, the RAG handler, computer controller and file manager, then starts the Socket.IO server under the `__main__` entry point. The listener has its own executable entry point and independently loads environment settings. [2] [3] [6]

## Concrete implemented features and flow

1. **Avatar UI and direct interaction.** The root Flask route renders `avatar.html`, which contains the canvas, prompt input, speak/ask controls, settings sidebar, speech bubble, Twitch listener controls and file-manager UI. `static/js/main.js` initializes speech, UI, Socket.IO, microphone, Live2D model, effects, history and initial config. Model assets are tracked under `models/`; backgrounds and audio effects live under `static/`. [2] [4] [7]
2. **Two AI provider paths.** `app.py` imports Ollama and Google’s Generative AI SDK, exposes provider/model/API-key settings in the interface/config, and dispatches AI requests through `call_ai_model`. Gemini calls include a four-second minimum-call interval and can use image input; Ollama supplies the local-model path. `process_ai_request` assembles the request context, including the configured persona and optional retrieved documents, then emits/returns the response. [2] [4]
3. **Prompt sources and conversational handling.** Prompts can come from the browser text UI, microphone transcription, or Twitch chat. The frontend sends through Socket.IO and the HTTP `/api/ask_ai` route; responses and errors are returned over HTTP and/or emitted as `ai_response`/`ai_error`. Socket handlers also expose conversation-history retrieval and clearing. Browser speech synthesis speaks returned text while avatar animations and speech bubbles provide visual feedback. [2] [7] [8]
4. **Twitch integration.** The listener connects to the configured channel, ignores its own echoed messages, filters repeated identical user messages within a configured time window, and only forwards user AI requests prefixed with `!ai`. It emits `trigger_ai_request` and `display_question` to the Flask process. It also parses configured follow/sub notification text from a named bot and emits speech and `trigger_event` events for celebrations. Flask has start/stop listener handlers that launch/manage the separate Python process. [3] [6]
5. **Document-grounded answers and file handling.** The RAG utility supports PDF and TXT ingestion and hybrid lexical/semantic retrieval. The file manager accepts only `.pdf` and `.txt` uploads, refreshes the index, lists documents from RAG and output directories, and deletes by category; Flask also provides categorized document download routes. [2] [9] [10]
6. **Vision and computer action paths.** The app contains Gemini multimodal handling for a supplied screenshot and Gemini function-calling dispatch to `ComputerController`. The controller exposes app/website opening, file creation/read/list, command execution, web search/scrape and link extraction actions. The UI labels computer control as Gemini-only and disabled by default in the markup/config. [2] [4] [11]
7. **Customization and stream effects.** Configurable persona, prompt, model/background, language/voice gender, wake-word, speech bubbles, RAG toggle, celebration messages/sounds and moderation-oriented prompt text are represented in the configuration/UI. The speech recognition code specifically tests for `webkitSpeechRecognition`, so browser compatibility varies. [2] [4] [8]

## Entry points, dependencies, tests

- **Main application:** `python app.py`; backend source and startup are in `app.py`. The README documents that launch command, but implementation is the basis for the architecture above. [2] [5]
- **Twitch process:** `python listener/twitch_listener.py`; this file constructs and runs a `TwitchBot` and Socket.IO client. The Flask app starts/stops this separate process through Socket.IO handlers. [3] [2]
- **Dependencies:** `requirements.txt` pins Flask 2.0.1, Werkzeug 2.0.1, Flask-SocketIO 5.3.2, Eventlet 0.40.3, requests 2.31.0, TwitchIO 2.3.0, python-dotenv 1.0.1, bleach 6.0.0, Ollama 0.1.0, python-socketio 5.12.1, langdetect 1.0.9, humanize 4.11.0, NumPy 2.2.2, PyMuPDF 1.25.3 and rank-bm25 0.2.2; it also lists setuptools, google-generativeai, Pillow, faiss-cpu, sentence-transformers and beautifulsoup4 without versions. `requests` is listed twice. [12]
- **Configuration:** `.env.example` includes Twitch token/client/channel settings, API/socket host and ports, AI model/provider-related values and toggles. Note that several actual required values are not given safe code defaults: listener config converts numeric fields and channel to expected types at import/startup, so empty/missing environment values can break it. The Flask code includes development/fallback secret values and defaults Socket.IO CORS to `*`. [2] [3] [13]

## Repo-specific integration value

This is a practical starting point for a desktop/browser VTuber companion that already connects three useful surfaces: browser-rendered avatar plus WebSocket control, Twitch chat/event listening in a separate process, and replaceable local/cloud LLM backends. The most reusable seams are Flask’s AI request functions and Socket.IO event protocol, the `TwitchBot` event/message handlers, the small `RAGHandler` abstraction, and modular browser components for model/speech/microphone/UI. An integrator can attach new chat platforms at the listener boundary, swap or add an AI provider around `call_ai_model`, reuse event types for avatar cues, or change retrieval independently. This is an integration opportunity inferred from those visible boundaries, not a claim that the code already supports additional platforms/providers. [2] [3] [6] [7] [9]

## Limitations and risks visible in code

- **Security posture needs hardening before network exposure.** `.env.example` sets `SOCKETIO_CORS_ALLOWED=*`, and Flask defaults to weak literal secret values. The server exposes configuration persistence, document upload/delete/download, Twitch token storage and AI actions without an evident authentication/authorization layer in the inspected routes. These are consequential if bound beyond a trusted local machine. [2] [13]
- **Computer control is powerful and safety is not fully enforced by the implementation.** The controller advertises `require_confirmation=True`, but its shown `execute_action` dispatches actions without an interactive confirmation step. Its command whitelist is implemented with `startswith` followed by `subprocess.run(..., shell=True)`, which merits careful review for command-boundary bypasses; file read/list operations also are not uniformly confined to the intended output directory. Enabling model function calling therefore expands the impact of prompt/tool misuse. [2] [11]
- **Twitch OAuth uses the implicit-token browser flow.** `twitch_auth.html` requests `response_type=token` and chat read/edit scopes; the callback extracts the token from the URL fragment and POSTs it for persistence. The inspected flow shows no OAuth `state` validation or server-side authorization-code exchange. Keep tokens secret and review the flow against current Twitch OAuth requirements before deployment. [15] [2]
- **Cross-process configuration is fragile.** Flask persists config to `.env`, but the listener is a separately launched process with its own import-time config; runtime update events mutate its in-memory values, while not all changes necessarily propagate into an already-established Twitch connection. Listener configuration parsing assumes non-empty numeric values and an available Socket.IO endpoint. [2] [3] [13]
- **RAG is simple and in-memory.** It re-embeds/rebuilds indices when initialized and does not persist vector indexes; TXT splitting uses blank-line paragraphs and BM25 tokenization is basic space splitting. Large corpora or robust incremental retrieval would require additional work. [9] [10]
- **Browser and model compatibility are uneven.** Voice recognition explicitly requires the prefixed WebKit API; model files span different Live2D formats, while the README describes Cubism 2 `.moc` compatibility but the tracked model tree includes both `.moc` and `.moc3` formats. Test actual model/runtime compatibility and target browsers rather than assuming all bundled models work identically. [4] [8] [5]
- **Maintenance signals:** dependency versions are mixed between pinned and unpinned, an old Google Generative AI package is used in code, and there is no automated test suite/config found. Validate current SDK/API compatibility and add tests around event flow, AI routing, file operations, OAuth and process lifecycle before extending it. [2] [12] [1]
- **License/asset due diligence:** the Bootstrap copyright line in the MIT license and the bundled avatar/runtime assets both warrant provenance checks. [14] [1]
